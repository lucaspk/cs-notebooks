Limite da ordenação por comparação

Objetivo: Derivar um limite inferior de pior caso a partir de decisões e permutações.

Pré-requisitos: Capítulos 02 e 13–15; contagem e logaritmos de math_disc.

Antes de começar

Conceitos e contrato

No modelo por comparação com n chaves distintas, cada teste binário entre chaves tem dois resultados possíveis. Uma árvore de decisão representa as comparações: cada caminho leva a uma ordem identificada. Há n! permutações possíveis, portanto ao menos n! folhas. Altura h permite no máximo 2^h folhas; logo o pior caso precisa de h≥teto(log₂(n!)) comparações. Para n crescente isso é Ω(n log n): o produto dos últimos cerca de n/2 fatores de n! já é pelo menos (n/2)^(n/2). O lab calcula o menor h cujo 2^h cobre n!, usando inteiros exatos. É limite necessário, não construção de algoritmo ótimo nem contagem exata de qualquer ordenação.

permutações = n!
h = 0; folhas = 1
enquanto folhas < permutações:
  folhas *= 2; h++

Exemplo trabalhado

Para n=3, existem seis permutações. Duas comparações distinguem no máximo quatro folhas; três permitem até oito. Logo algum caso exige pelo menos três comparações. Isso não obriga toda entrada a gastar três.

Limites do modelo +

Gabarito +

Pré-teste

pretest: Não. Melhor caso, caso observado e pior caso são afirmações diferentes.

Exemplo trabalhado

worked-observation: Oito é capacidade máxima de uma árvore binária de altura três. O domínio tem só seis permutações; caminhos podem faltar ou ser impossíveis.

Previsão

predict: 4!=24; quatro decisões permitem 16 folhas, insuficientes; cinco permitem 32. Limite cinco comparações.

Comparação

compare: Permutações 1,1,6,24,120; limites 0,0,3,5,7. Fatorial cresce por fator n, não por fator dois fixo.

Transferência

design-transfer: Não. Acesso por valor e contagem exploram domínio limitado, fora do modelo que aprende a ordem apenas por comparações binárias entre chaves. É necessário contabilizar o tamanho do domínio.

Checkpoint

checkpoint-explain: Chaves distintas, todas as permutações admissíveis, decisões binárias por comparação. Ω(n log n) é necessidade de pior caso de qualquer algoritmo nesse modelo; Θ(n log n) do merge sort é custo de uma implementação específica, compatível com a necessidade.

Limites

Critérios
