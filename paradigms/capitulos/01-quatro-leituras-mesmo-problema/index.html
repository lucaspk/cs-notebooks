CAPÍTULO 01

Quatro leituras
do mesmo problema

Objetivo deste capítulo: somar uma lista e comparar quatro formas explícitas de escrever o mesmo cálculo. Cada forma usa o mesmo problema — não suponha conhecimento prévio de nenhum paradigma.

Pré-teste

ANTES

Sem abrir a teoria.

1. “Paradigma de linguagem” é o nome do editor ou o estilo de organizar o programa?

2. Dois programas com estilos diferentes podem imprimir o mesmo resultado?

Quais são as quatro leituras?

CONTEXTUALIZE

1. Imperativo

total = 0; percorra a lista com um loop e some cada número a total. A variável acumuladora muda durante a execução.

2. Dobragem explícita

Ainda percorra a lista, mas escreva a soma como uma regra de atualizar acumulador: total = total + número. O “dobrar” é separar o estado inicial da função que o combina com cada item.

3. Reduce

Entregue ao método reduce um valor inicial e uma função que combina o acumulador com o próximo número. Não há loop escrito por você.

4. Pipeline

Observe o mesmo cálculo como uma sequência de valores: comece em 0 e aplique a operação “somar próximo” a cada item da lista.

Estas quatro alternativas são apenas leituras didáticas deste capítulo. Não estamos alegando que “pipeline” ou “dobragem” são outra operação matemática: todas implementam a soma dos elementos.

Previsão

ANTES DO LAB

Agora que você conhece as quatro formas, calcule manualmente 1 + 2 + 3 + 4. Depois escreva: qual soma espera e se espera algum estilo dar outro valor. Justifique a previsão usando o que acabou de ler.

Resposta sugerida +

Checkpoint

Gabarito +

As quatro leituras

1. Imperativo: loop explícito com variável total que muda.

2. Dobragem explícita: define a regra total = total + item para combinar estado e próximo elemento.

3. Reduce: delega a combinação ao método reduce, usando valor inicial e função combinadora.

4. Pipeline: representa a mesma combinação como uma sequência de operações sobre o valor acumulado.

Pré-teste

# Campo — Essência

1 pretest-paradigm — Paradigma = estilo de organizar programa (não é linguagem nem editor).

2 pretest-same — Mesmo problema pode ter várias leituras; o resultado numérico pode coincidir.

Previsão (`predict-same-sum`)

Lista 1 2 3 4: os quatro estilos devem dar 10 com passos parecidos (um passo por elemento + início).

Comparar

Campo Essência

compare-steps Imperativo e reduce costumam ter o mesmo número de passos neste modelo; diferença é *como* se expressa o acumulador (loop explícito vs função de ordem superior).

compare-style Estilo não muda resultado aqui; muda legibilidade, composição e risco ao mudar o código.

MC (`mc-ch01`)

Correta: B — paradigma descreve organização do programa; trocar for por reduce não muda a soma neste lab.

Checkpoint

# Campo — Essência

1 checkpoint-paradigm — Imperativo: passos e estado mutável; funcional leve: encadear transformações / fold.

2 checkpoint-why — Ler labs de outros livros exige reconhecer estilo (mutação vs imutável, OO vs funções).

3 checkpoint-result — Quatro leituras, um resultado quando a operação é a mesma.

Teoria +

Paradigma não é marca de linguagem: é convenção de como estruturar estado, controle e abstração. Livros como prog_conc misturam estilos nos labs de propósito.
